Purpose: show that the Paper 0 reference model is plainly hand-editable,
so re-analysis with alternative interiors — including MSL-free thermally
consistent models — needs no special tooling.

## 1. The model file format

The reference model is a plain-text TauP `.nd` (named-discontinuity) file,
35 lines, four columns per layer line:

```
depth_km   Vp_km_s   Vs_km_s   rho_g_cm3
```

- A **repeated depth** on consecutive lines is a first-order discontinuity.
- The bare lines `outer-core` and `inner-core` name the CMB and ICB. Both
  names must be present for TauP to define core phases; without
  `inner-core` there is no ICB and hence no PKiKP branch at all.
- Canonical file: `paper0_ref_1800.00-5.00-5.80-600.00-0.300.nd`
  (in the capsule at `data/models/`, and in this directory at
  `artifact/models/M0/`; SHA-256
  `400ec3cf3158ec051f54abebc7c3c9724f2c342fc0ad765464c88f2435057d07`;
  compiled NPZ `e73222e22fd5c319476faf05864f4c360d03fd96bb103bde0897340c38e64de0`).
  No MSL; CMB at depth 1589.5 km (radius 1800.0 km for R_Mars 3389.5 km);
  ICB at radius 600.0 km.

## 2. Worked example: add a molten silicate layer (model M1)

Copy the canonical file, then replace its two deepest mantle lines with a
150-km liquid-like layer directly above the CMB (radius 1800–1950 km =
depth 1439.5–1589.5 km): Vp = 5.00 km/s constant, Vs = 0.001 km/s (the
community TauP-compatibility convention for molten silicate; see §4),
density kept from the canonical gradient. The exact diff that ran:

```diff
 12,13c12,15
 < 1536.8360	  10.0611	  5.0448	  4.6990
 < 1589.5000	  10.0611	  5.0448	  4.6990
 ---
 > 1439.5000	  9.9802	  4.8907	  4.4550
 > 1439.5000	  5.0000	  0.0010	  4.4550
 > 1536.8360	  5.0000	  0.0010	  4.6990
 > 1589.5000	  5.0000	  0.0010	  4.6990
```

(The first added line closes the solid mantle at 1439.5 km; the repeated
depth creates the discontinuity into the MSL. The resulting file is
`artifact/models/M1/M1_msl_added_1800.00-5.00-5.80-600.00-0.300.nd`.)

Compile and query:

```sh
export MPLCONFIGDIR=$PWD/.mplcache   # keeps matplotlib cache out of $HOME
python -c 'from obspy.taup import taup_create; taup_create.build_taup_model(
    filename="models/M1/M1_msl_added_1800.00-5.00-5.80-600.00-0.300.nd",
    output_folder="models/M1")'
python - <<'EOF'
from obspy.taup import TauPyModel
m = TauPyModel(model="models/M1/M1_msl_added_1800.00-5.00-5.80-600.00-0.300.npz")
for a in m.get_travel_times(source_depth_in_km=33, distance_in_degree=29.0,
                            phase_list=["ttall"]):
    if "PKiKP" in a.phase.name:
        print(a.phase.name, round(a.time, 3), round(a.ray_param_sec_degree, 4))
EOF
```

Verified outcome (2026-08-17 sweep): M1's PKiKP arrives **+30.292 s** after
the canonical model's, with pPKiKP/sPKiKP shifted by the same amount.

## 3. Parametric variants (no hand edit)

Core-family variants (CMB radius, inner-core radius, core velocities) are
generated by the capsule scripts
`scripts/05_model_gen/generate_nd_model.py` + `scripts/core_profile.py` —
this is how the canonical model itself and the M2/M3 variants exist. The
canonical regeneration is byte-identical to the committed file (registered
positive control, re-verified in the annex run).

## 4. Conventions and traps (measured, not hypothetical)

1. **Fluid outer core**: Vs = 0 exactly, between the `outer-core` and
   `inner-core` names.
2. **MSL Vs convention and build cost**: community releases (e.g. the Khan
   et al. 2023 TauP-ready ensemble) encode molten silicate with
   Vs = 0.001 km/s. TauP slowness is r/v, so this creates S-slowness values
   of order 10⁶ s that ObsPy's sampler must subdivide at its default
   `max_delta_p` — the build then takes **hours instead of seconds**
   (canonical model 2.9 s measured; MSL-bearing models measured 3.4 h for
   the generated mantle+MSL hybrid and 3 h 41 m / 51,006 S layers for the
   Khan as-released member, on the same machine). The process is slow,
   not hung: we verified by periodic stack sampling that the sampler's
   loop state advances steadily through the MSL slowness span. Budget
   accordingly; do not change sampler tolerances to force speed — that
   alters sampling fidelity.
3. **Degenerate placeholder cores**: the Khan release's `README.txt` states
   its small inner core is "entirely unrelated to the inversion results"
   (radius 0.5 km in the member we queried). An ICB at r ≈ 0.5 km defines
   ICB-reflection phases only as a degenerate limit — verified by
   computation: the member's PKiKP/pPKiKP/sPKiKP rows all carry ray
   parameter exactly 0.0 s/deg (a vertical central reflection reported at
   29°), ~181 s late, and phases crossing the MSL as shear arrive at
   ~10⁵–10⁶ s (ScS = 290,039 s ≈ 2 × 150 km / 0.001 km/s) — convention
   artifacts, not physics. To carry such a model's
   mantle/MSL physics into PKiKP questions, graft a resolvable core at the
   file's own mantle/outer-core boundary (our M4b construction: R_OC from
   the file's recorded boundary; parametric outer-core profile and inner
   core as in §3). Record the graft as a hybrid — it is no longer "the
   released model".
4. **Absent branches are data**: if a model produces no PKiKP (no ICB, or
   geometry outside the branch), record the branch as absent. Do not impute.

## 5. Acceptance gates for any edited model

1. Build exits 0; the `.npz` loads via `TauPyModel`; the registered
   geometry returns ≥1 finite arrival.
2. Sign/physics controls (both verified in the annex run): an added
   low-velocity layer above the CMB must *delay* PKiKP
   (M1: +30.292 s); PKiKP time must *decrease* with growing inner-core
   radius (verified 843.546 s → 808.136 s → 772.762 s for R_IC
   500 → 600 → 700 km — the corresponding `.nd` files are in
   `artifact/models/M3a` and `artifact/models/M3b`). A violated control
   means a broken edit or harness, not a discovery.
3. Record SHA-256 of the `.nd` and `.npz` in a manifest next to the run.

## 6. Plugging into the comparison harness

The annex comparison harness computes, for every model in its `MODELS`
dict, the full `ttall` table at the registered geometry (source 33 km,
29.0°), differentials vs first P and vs the canonical model, and the
consistency columns against the registered comparison points. Adding a
model is one dict entry; models whose `.npz` is not yet built are carried
as explicit `PENDING-COMPLETION` disposition rows rather than aborting
the sweep. The harness and its full output table ship with the
revision's evidence deposit; the per-model file hashes it pins are
already in `artifact/MODEL_MANIFEST_sha256.txt` here.
